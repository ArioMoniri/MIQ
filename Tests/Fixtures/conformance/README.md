# Conformance corpus (contract version 1)

Tiny reference volumes plus the values a conforming reader must report for each.
Shared by MIQ (macOS, Swift — `Tests/MIQCoreTests/ConformanceCorpusTests.swift`) and
its Windows sibling MIQ-Win, so both previewers agree on geometry, orientation and
pixel data for the same file.

Everything here is generated by `scripts/dev/make_conformance_corpus.py` (Python
standard library only). The script computes the expected values itself, from the voxel
arrays it writes — not by running either reader — so passing the corpus means agreeing
with this contract, not just with the other implementation.

## Layout

```
index.json                 {"contractVersion": 1, "cases": ["<case>", ...]}
<case>/image.<ext>         the reference file (.nii, .nii.gz, .mgz, .mif, .nrrd)
<case>/expected.json       what a reader must report for it
```

| Case | What it pins |
|---|---|
| `nifti1_ras_float32` | sform (code 2) RAS, anisotropic spacing 1×2×3 |
| `nifti1_las_int16` | sform LAS (negative x), negative int16 values |
| `nifti1_lps_uint8_gz` | gzip'd, sform LPS, uint8 |
| `nifti1_oblique_sform` | 60° rotation about x → dominant-axis code `RSP` |
| `nifti1_qform_only` | sform_code 0 (rows present but ignored), qform 180° about z with qfac −1 → `LPI` |
| `nifti1_no_orientation` | qform_code = sform_code = 0 → `unknown` |
| `nifti2_4d_float64` | NIfTI-2, 3 volumes, float64 |
| `nifti1_int16_scaled_gz` | scl_slope 0.5, scl_inter −10 |
| `nifti1_uint8_labels_gz` | uint8 label map |
| `mgh_lia_int16` | compressed MGH, FreeSurfer conformed `LIA` |
| `mif_layout_permuted` | MIF layout `-0,+2,+1` (reversed + permuted storage) → `LSA` |
| `nrrd_lps_gzip` | NRRD gzip encoding, `space: left-posterior-superior` |
| `nrrd_no_space` | NRRD with no `space` / `space directions` → `unknown` (**pending**, see below) |

All spatial extents are odd (5×7×9 in storage space), so a center index means the same
physical slice whichever end of an axis it is counted from. Total size is ~50 KB.

## expected.json

```jsonc
{
  "contractVersion": 1,
  "file": "image.nii",
  "format": "nifti1",              // nifti1 | nifti2 | mgh | mif | nrrd
  "description": "…",
  "dims": [5, 7, 9],               // storage-space extents (see below)
  "volumes": 1,                    // 4th dimension, >= 1
  "spacing": [1.0, 2.0, 3.0],      // mm per storage axis, as the header states it
  "datatype": "float32",           // uint8 int8 uint16 int16 uint32 int32 uint64 int64 float32 float64 rgb24 rgba32
  "orientation": "RAS",            // 3-letter storage orientation code, or "unknown"
  "effectiveScaling": {"slope": 1.0, "inter": 0.0},
  "probes": [{"x": 0, "y": 0, "z": 0, "t": 0, "value": 0.5}, …],
  "slices": [{"mode": "stored", "plane": "axial", "volume": 0, "sliceAxis": 2,
              "sliceIndex": 4, "width": 5, "height": 7, "sha256": "…"}, …],
  "pending": null                  // or a reason string, see below
}
```

### Storage space

All per-axis fields (`dims`, `spacing`, the orientation letters, probe coordinates,
`sliceAxis`) are in the reader's *storage space*: three spatial axes in on-disk traversal
order, axis 0 varying fastest, then the volume index.

- NIfTI-1/2, MGH: the file's own axis order (`dim[1..3]`, `width/height/depth`).
- NRRD: the three axes that have a `space directions` vector, in file order; with no
  `space directions`, the first three axes.
- MIF: the image axes sorted by `layout` rank (`abs` of the entry; 0 = fastest). A
  reversed entry (`-`) does not change the traversal: storage index *i* is the *i*-th
  element along that axis in the file. E.g. `dim: 5,9,7` with `layout: -0,+2,+1` has
  storage dims `5,7,9`.

### orientation

For each storage axis, the anatomical direction of +index, as one letter
(`R`/`L`, `A`/`P`, `S`/`I`), concatenated. Derived from the axis's world-space direction
vector (RAS+ basis) by its dominant component — ties resolve R/L over A/P over S/I — with
the sign giving the letter. If any axis vector is zero, or two axes share a world axis,
the orientation is `unknown`.

Direction vectors by format:

- NIfTI: sform columns when `sform_code > 0` and non-degenerate; else the qform rotation
  (quaternion b, c, d; `qfac` = sign of `pixdim[0]`, −1 reflects the third column) when
  `qform_code > 0`; else `unknown`.
- MGH: the `x_ras`, `y_ras`, `z_ras` direction cosines when `goodRASFlag != 0`; else `unknown`.
- MIF: the `transform:` columns (identity when absent) for each image axis, permuted into
  storage order and negated for reversed `layout` entries.
- NRRD: each `space directions` vector, converted to RAS by the `space` field (e.g. LPS
  negates x and y). No `space directions` → `unknown`.

### effectiveScaling and probes

A voxel's value is `raw * slope + inter`, computed in float32 (two roundings, no fused
multiply-add). `effectiveScaling` is the pair actually applied: NIfTI `scl_slope = 0` (or a
non-finite pair) means no scaling and reports `{1, 0}`; MIF `scaling: offset,scale`; MGH
and NRRD are always `{1, 0}`. Each probe is the value at storage coordinate (x, y, z, t).
The corpus values are exactly representable, so they compare with `==`.

### slices — the canonical center slice

For each `mode` ∈ {`stored`, `neurological`}, `plane` ∈ {`axial`, `coronal`, `sagittal`},
and `volume` (0, plus the last volume for 4D files), a plan picks three distinct storage
axes — `sliceAxis` (s), horizontal (h), vertical (v) — and a direction for h and v:

- **stored**: coronal s=1, h=0, v=2; sagittal s=0, h=1, v=2; axial s=2, h=0, v=1.
  Columns run h forward (index 0 at the left); rows run v *backward* (the highest index
  is the top row).
- **neurological**: pick the storage axis whose orientation letter lies on each target
  world axis, then orient so that
  - axial: slice ⟂ S/I; columns L→R (patient right on the viewer's right); rows A at top;
  - coronal: slice ⟂ A/P; columns L→R; rows S at top;
  - sagittal: slice ⟂ R/L; columns A→P (anterior on the viewer's left); rows S at top.

  When `orientation` is `unknown`, neurological falls back to the stored plan.

`sliceIndex = floor(dims[s] / 2)` (a storage index). The slice is `width = dims[h]`
columns by `height = dims[v]` rows. Its canonical bytes are each value (scaled, as above)
as an IEEE-754 float32, little-endian, in row-major order starting from the top-left
pixel. `sha256` is the lowercase hex SHA-256 of those bytes. In pseudo-code:

```
for row in 0..<height:            # 0 = top
  for col in 0..<width:           # 0 = left
    c[s] = sliceIndex
    c[h] = hReversed ? dims[h]-1-col : col
    c[v] = vReversed ? dims[v]-1-row : row
    emit float32_le(value(c, volume))
```

with `hReversed = false, vReversed = true` for stored; for neurological,
`hReversed = (axis h points the opposite way to the wanted left→right / A→P run)` and
`vReversed = (axis v points toward the top-of-image direction)` — exactly
`plan()` in `make_conformance_corpus.py`, which is the normative reference.

This is the raw data a viewer windows and resamples for display — not the rendered
pixels, which depend on percentile settings and screen size.

## pending

`pending` is `null`, or the reason a case encodes behaviour that has not landed yet in
MIQCore. Readers should run pending cases but may report them as expected failures.
Currently `nrrd_no_space` is pending: MIQCore assumes RAS for an NRRD without `space`;
the contract says `unknown` (and so its neurological sagittal slice is the stored one).
MIQ runs it in a disabled test (`conformsPending`) until the orientation change lands.

## Regenerating / changing the corpus

```
python3 scripts/dev/make_conformance_corpus.py      # writes Tests/Fixtures/conformance
```

Output is deterministic (gzip mtime 0), so an unchanged script leaves the files
unchanged. After any change, run MIQCore's suite (`ConformanceCorpusTests`); to see what
MIQCore actually reports for a failing case, in expected.json shape, run it with
`MIQ_CONFORMANCE_DUMP=1`. A change to a field's *meaning* bumps `CONTRACT_VERSION` in the
script; adding cases does not.

## Consuming from MIQ-Win

Copy (or submodule) this directory unchanged. For each name in `index.json`, open
`<case>/<file>` through the normal file-loading path and compare every field above;
spacing within 1e-5, everything else exactly. Implement the SHA-256 over the canonical
bytes from your own slice extraction — that one hash per plane/mode pins the axis
mapping, the reversal rules, the datatype decode, endianness and scaling at once.
